Microsoft Teams — Protocol Handler Abuse

Any webpage can silently invoke Teams' 10 registered protocol handlers without user confirmation. Visiting this page from a Windows machine with Teams installed demonstrates that sip://, callto://, im://, and other schemes launch Teams directly — no browser confirmation dialog on Windows.

Target MS Teams v26198.304.4946.9672 (Windows)
Severity Medium — CVSS:3.1/AV:N/AC:L/PR:N/UI:R/S:U/C:N/I:L/A:L
Handler path HKCU\Software\Classes\<scheme>\shell\open\command
Requires Teams installed, user visits page (Windows only)

Attack Scenarios
A1 Direct Anchor Link

A regular <a href="sip://…"> tag triggers the Teams call dialog when clicked. No browser confirmation shown for sip://, callto://, im:// or tel:// on most Windows configurations.

// HTML on attacker page <a href="sip://target@contoso.com"> Click here to view report </a>
ready Fire sip:// link
A2 JavaScript Location Override

Setting window.location to a protocol URI fires the handler silently — no click required, runs from any inline script.

// Fires on page load, no click window.location = "sip://" + target;
ready
A3 callto:// — Unsolicited Call

callto:// and tel:// open the Teams call UI targeting the victim's address. The victim sees an outgoing call attempt appear on their screen. Can be triggered by visiting any webpage.

// Initiates unsolicited call window.location = "callto://" + target;
ready
A4 Hidden iframe — Zero Visible Interaction

Setting a 0×0 hidden <iframe> src to a protocol URI fires the handler without the user seeing any element. Can be injected into existing pages via XSS or ad injection.

// 0×0 hidden iframe trigger var f = document.createElement('iframe'); f.style.cssText = 'display:none'; f.src = "im://" + target; document.body.appendChild(f);
ready

Attack chain
1. Victim visits any webpage (attacker-controlled or via ad injection)
2. Page sets window.location = "sip://victim@domain.com"
3. Browser dispatches URI to Windows Shell
4. Shell invokes ms-teams.exe "sip://victim@domain.com"
5. Teams foregrounds and initiates call attempt
↳ No confirmation dialog shown for sip:// / callto:// / im:// / tel://
Impact summary
• Unsolicited Teams call attempt to any SIP address
• Teams foreground hijack (focus theft) from any page
• Phishing amplifier: msteams:// deep links open crafted meeting/chat URLs
• No admin privileges required (HKCU, not HKLM)
• Works across all major browsers on Windows
• ldap:// handler: unexpected LDAP queries from Teams process
